# D47. 构建产物不进版本管理

- **状态**：待实施
- **关联**：D36、D45
- **现状**：`lib/` 被版本管理跟踪，但只在发版时重建并随发版提交提交，平时工作区里留着一个改过的 `lib/client.js`

## 决定

- `lib/`（以及 D46 之后各包的构建输出）加入 `.gitignore`，不再提交。
- 持续集成负责构建；发版时由持续集成构建、打包并发布到 npm，发布的内容与通过测试的构建是同一份。
- 从 git 直接安装插件的用法需要先构建，README 写明。

## 理由

- 被跟踪却只在发版时更新的产物既不是源码，也不能保证是最新的，平时只会以「改过的文件」出现在工作区里。

## 代价

- 无法再从仓库的某个提交直接拿到可用的产物，必须构建或从 npm 安装。

## 重审条件

- DSH 的插件市场要求从 git 仓库直接加载产物时，改为在独立的发布分支上提交产物。
