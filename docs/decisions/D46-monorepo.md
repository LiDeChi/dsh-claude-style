# D46. monorepo 布局，对外仍是一个插件

- **状态**：待实施
- **关联**：取代 D18 与 D8；D7、D10、D36、D38
- **现状**：单包仓库。`src/core/`（宿主访问、偏好、模型文案、i18n、调度器）、`src/shared/`（多个功能共用的部件，脚本与样式放在一起）、`src/theme/`（不属于任何功能的全局外观）、`src/features/<功能>/`（一个功能的安装器、拆出的部分与样式表）、`host/`（宿主半边）、`lib/`（构建产物）、`scripts/`（构建与测试）

## 决定

- 用 npm workspaces 组织：
  - `packages/client`：浏览器半边；内部仍按功能分目录，一个功能的脚本与样式放在同一目录、主文件以功能命名，多个功能共用的部件单独成层，不属于任何功能的全局外观单独成层。
  - `packages/host`：宿主半边，同样改用 TypeScript。
  - `packages/contracts`：两半共用的常量、路由名、偏好键与默认值（D10）、宿主契约（D44）。
  - `packages/assets`：资源与清单生成（D38）。
  - `packages/testing`：模拟模型服务、轨迹记录工具（D45）。
- 对外只发布一个插件（D7）。
- 组织规则：
  - 同一段宿主查询或同一种写法出现第 3 次时收进共用层，不写第三份。
  - 文件接近 750 行时停止加功能、按职责拆分，拆分前等用户确认，之前只修缺陷。
  - 功能之间不借用类名，共用外观用中性类名（`dsh-claude-popover-card`、`dsh-claude-popover-item` 等）。
  - 以上能机器检查的由 lint 执行。
- 多主题：只换色板与标志时用现有的品牌切换在包内解决；新主题出现行为分歧（不同的 DOM 覆盖、不同的输入框结构）时，拆成 `packages/` 下的独立主题包，共用部分留在共用包里。

## 理由

- 两半各写一份常量与偏好声明、构建逐键核对，是因为没有共用的地方；有了 `contracts` 包，这份核对就不需要了。
- 资源、测试工具与两半代码的依赖关系不同，分包后各自的构建与测试边界清楚。

## 代价

- 工作区配置与包之间的引用多一层；全仓库路径一次性变动，搬动与改逻辑分开提交。

## 重审条件

- 出现第二个真实使用者需要单独依赖其中某个包时，把它独立发布。
