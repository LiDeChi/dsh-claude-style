# D38. 资源只有一条路径：内容哈希清单与通用资产路由

- **状态**：待实施
- **关联**：取代 D24 的帧图交付方式；改写 D11 的公开资产；D12、D36、D46
- **现状**：螃蟹的帧图（约 14 KB）在构建时转成 base64 内联进产物（`CRAB_SHEET_URLS`）；Deepy 的帧图（约 0.4 MB）复制到 `lib/deepy/`，宿主半边在 `/dsh-claude-style/deepy/<名字>.png` 提供，浏览器第一次要演某个动画时加载、在画布上把像素重建成 SVG、以内容戳加转换器版本为键存进 Cache API；品牌标志与厂商组合标内联；字体与模型文案走宿主路由

## 决定

- 所有图片与图形资源（螃蟹、Deepy、品牌标志、厂商组合标）放进同一个资源目录，构建时生成带内容哈希的清单。
- 小于阈值的资源自动内联成数据地址；其余由宿主半边的一条通用路由 `/dsh-claude-style/assets/<hash>.<ext>` 提供。文件名只接受清单里出现过的哈希加扩展名，读取只落在构建产出的资源目录里（D11）；地址带内容哈希，可以长期缓存。
- Deepy 的像素到矢量的转换挪到构建时：构建产出 SVG（按颜色各一条 path、同行同色游程合并、每格四周留 `DEEPY_GUTTER` 透明边），路由以 brotli 预压缩发送。浏览器端的画布转换、Cache API 缓存与两处相关的 catch（D12）删除。
- 帧图与动画登记表的对应关系、帧数、裁切框、静止帧的合法性，在生成清单时检查。
- 新增一个角色或一张图，只需把文件放进资源目录并在登记表里登记，不必再决定走哪条路。

## 理由

- 两条交付路径各自合理，但每加一种资源都要先判断走哪一条，路径的选择应该由大小自动决定。
- 浏览器端重建矢量的唯一目的是播放矢量图；构建时做完，运行时只剩加载。
- SVG 的文本压缩率高，预压缩后传输体积与 PNG 相近。

## 代价

- 宿主半边多一条通用路由；更新插件后没有重启宿主时，旧的宿主半边没有这条路由，超过阈值的资源读不到（对应的动画或图形缺席，控制台说一次）。
- 构建多一步矢量化与压缩。

## 重审条件

- DSH 加载器支持资产 URL 时，资源改随客户端包分发，删除这条路由。
